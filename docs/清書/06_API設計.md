# API設計

本書は、[05_要件定義.md](05_要件定義.md) の要件を、**HTTP インターフェースの形**に落とす。

> **本書のスコープ**
> - **含む**：URL とメソッド、リクエスト／レスポンスの形、認証・認可の通し方、ページング等の規約。
> - **含まない**：テーブル・カラムの実装、画面構成と文言。
>
> 現時点ではホーム画面まわりから着手しており、全体は順次拡充する。

---

## 0. 共通規約（本書全体で前提とするもの）

| 項目 | 決定 |
|---|---|
| 名前空間 | `/api/staff/*`・`/api/family/*`・`/api/admin/*`。主体ごとに分ける |
| 認証主体の識別 | 職員はセッションから解決する。**`staffId` をパス／クエリ／ボディで受け取らない**——同一施設内の他職員の反応を、IDを差し替えて覗ける経路を作らないため |
| クライアントが送ってよい識別子 | 同一施設内で自由に選べるもの（`postId`・`residentId` 等）に限る |
| 識別子の形式 | UUIDv7 の文字列表現 |
| 日時 | RFC 3339・UTC・秒精度（`2026-09-12T04:31:00Z`） |
| 一覧の形 | `{ "items": [...], "nextCursor": "…" \| null }`。カーソルは不透明な文字列 |
| 並び順 | 時刻の降順のみ。**件数・多寡による並べ替え／集計は行わない**（同僚間の比較を助長しないため） |
| テナント分離 | 施設IDはURL・ボディに現れない。セッションから解決したうえで、全クエリに絞り込みをかける |

## 1. GET /api/staff/reactions

ログイン中の職員宛てに届いた反応を、新しい順の一覧で返す。ホーム画面が最初に表示する内容。

### 1-1. 対応する要件

- FR-302：反応は投稿を行った職員本人に届く
- FR-303：職員は自分の投稿に届いた反応を一覧で確認できる

### 1-2. 認可

- 対象は**リクエストした職員自身の投稿に対する反応のみ**（権限マトリクス「自施設の全投稿・全反応の閲覧」＝職員は△＝自分の投稿への反応に限る）
- `staffId` はセッションから解決し、他職員の反応をクエリで指定する経路は存在しない
- 未認証は `401`

### 1-3. リクエスト

```
GET /api/staff/reactions?cursor={opaque}&limit={n}
```

| パラメータ | 必須 | 内容 |
|---|---|---|
| `cursor` | 任意 | 前回レスポンスの `nextCursor`。初回は省略 |
| `limit` | 任意 | 既定20・上限50 |

### 1-4. レスポンス

```json
{
  "items": [
    {
      "id": "0192f8a1-4b2c-7d3e-9a10-1b5c6e2b4d31",
      "reactedAt": "2026-09-12T05:02:11Z",
      "familyMember": {
        "name": "山田 恵子",
        "relationship": "娘"
      },
      "post": {
        "id": "0192f7a1-3c4e-7b2d-9f10-8a5c6e2b4d31",
        "postedAt": "2026-09-12T04:31:00Z",
        "text": "お昼にお庭を散歩しました",
        "photo": {
          "url": "/api/staff/photos/0192f7a1-3c4e-7b2d-9f10-8a5c6e2b4d31",
          "width": 1600,
          "height": 1200
        },
        "resident": { "name": "田中 太郎" }
      }
    }
  ],
  "nextCursor": null
}
```

| フィールド | 要点 |
|---|---|
| `id` | 反応そのものの識別子（取り消し可否の判定には使わない。反応は職員側からは取り消せない） |
| `familyMember.name` / `relationship` | **氏名と続柄まで開示する。** 「誰から届いたか」を職員が実感できることが FR-302 の狙い（K3：反応が戻らない、の解消）。**家族側の識別子（`familyMemberId`）は返さない**——職員が家族に直接連絡する経路を作らないため（家族の連絡先はこのシステムの外にある） |
| `post.text` / `post.photo` / `post.resident.name` | 投稿の要約のみ。**投稿の状態（`status`）・削除日時・投稿者情報は含めない**——投稿本体の詳細は `/api/staff/posts` の責務であり、本エンドポイントは「誰の投稿に、誰から反応が来たか」の把握に必要な最小限に絞る |
| 反応の取り消し | 表現しない。家族が取り消すと、次回取得時にこの一覧から**消える**（取り消し済みという状態は返さない） |

## 2. GET /api/family/timeline

紐づく入居者の投稿を、新しい順の一覧で返す。家族がアプリを開いて最初に表示する内容。

### 2-1. 対応する要件

- FR-201：家族は、紐づく入居者の投稿を閲覧できる
- NFR-41：家族は自分が紐づく入居者の情報のみにアクセスできる

### 2-2. 認可

- 対象は**リクエストした家族自身が紐づく入居者の投稿のみ**（権限マトリクス「紐づく入居者の投稿の閲覧」＝家族は○、他の入居者は不可）
- 紐づく入居者（`residentId`）はセッションから解決し、クライアントが指定する経路は存在しない
- MVPでは家族1名につき紐づく入居者は1名を前提とする（05_要件定義.md 9-1「1人の家族が複数の入居者に紐づく」はスコープ外）
- 未認証は `401`

### 2-3. リクエスト

```
GET /api/family/timeline?cursor={opaque}&limit={n}
```

| パラメータ | 必須 | 内容 |
|---|---|---|
| `cursor` | 任意 | 前回レスポンスの `nextCursor`。初回は省略。復号できない値は `400` |
| `limit` | 任意 | 既定20・上限50。整数でない値・1未満・50超は `400`（黙って丸めない） |

### 2-4. レスポンス

```json
{
  "items": [
    {
      "id": "0192f7a1-3c4e-7b2d-9f10-8a5c6e2b4d31",
      "postedAt": "2026-09-12T04:31:00Z",
      "text": "お昼にお庭を散歩しました",
      "photo": {
        "url": "https://photos.example.invalid/0192f7a1-3c4e-7b2d-9f10-8a5c6e2b4d31?...",
        "width": 1600,
        "height": 1200
      },
      "resident": { "name": "田中 太郎" }
    }
  ],
  "nextCursor": null
}
```

| フィールド | 要点 |
|---|---|
| `photo` | **null にならない。** FR-101 により、投稿には写真1枚が必須のため |
| `photo.url` | **そのまま使う URL**であり、クライアントは組み立てない（NFR-44：推測可能なURLで第三者に到達させない）。URL の形はサーバー側の保管先に従う（本番はS3の署名付きURL）ため、形に依存した実装をしてはならない |
| `resident.name` | MVPは家族1名につき入居者1名の前提（2-2）のため、全件で同じ値になる。将来複数紐づけを許すときに意味を持つ |
| 投稿者（職員／入居者本人）の情報 | 含めない。家族向け画面に「誰が発信したか」を出す要件が無く、NFR-13（家族向けにシステム用語・内部構造を持ち込まない）の方針にも沿う |
| 投稿の状態・削除日時 | 含めない。削除された投稿は次回取得時に一覧から**消える**（1-4の反応と同じ扱い） |
