# このシステムでできること（非エンジニア向けのご説明）

このページは、施設で暮らす高齢の方と、そのご家族をつなぐ仕組みについて、**専門用語を使わずに**ご説明するものです。

- 読む人：施設長・職員のみなさま、ご家族、この取り組みを知りたい方
- 書いていること：**誰が・何をできて・何が起きるか**
- 書いていないこと：画面の細かい作り、内部の仕組み、費用の見積もりの根拠

> 技術者向けの詳しい仕様は [05_要件定義.md](05_要件定義.md) 以降にあります。このページとの対応は最後の「13. 詳しい資料との対応」にまとめました。
> 内容が食い違った場合は、詳しい仕様のほうが正です。

---

## 1. ひとことで言うと

**施設での「今日の様子」を、写真1枚で、ご家族一人ひとりに直接お届けする仕組みです。**

そして、受け取ったご家族が**ボタンをひとつ押すだけ**で「ありがとう」を返せて、その気持ちが**写真を撮った職員本人に届きます**。

大事なのは、次の3つです。

| | |
|---|---|
| **送るのが簡単** | 職員が手元の端末で撮って、数十秒で送れる。文章を書くのは任意 |
| **まっすぐ届く** | ご家族の代表者を経由せず、登録されたご家族全員に同時に届く |
| **返事が返る** | ご家族の反応が、施設宛てではなく「撮った職員本人」に戻る |

---

## 2. なぜ作るのか（今、何が起きているか）

現在、施設からご家族への連絡は、こういう形になりがちです。

- 職員は日々たくさんの記録を書いているが、**それはご家族には届かない**（記録は施設内部のもの）
- ご家族に何かを伝えるときは、**代表のお一人に電話**する。そこから他のご家族へ、また聞きで広がる
- 代表の方が忙しいと、**他のご家族には何も届かない**
- 情報が少ないので、ご家族は不安になって**施設に問い合わせる**。その電話は施設長に集中する
- ご家族が「ありがとう」と思っても、**それを職員に伝える手段がない**

結果として、**一番様子を知りたい方ほど、何も知らないまま**になります。たとえば遠方で一人暮らしをしている配偶者の方は、息子さんからの又聞きでしか近況を知ることができません。

この仕組みは、この流れを

**「職員が送る」→「ご家族全員に直接届く」→「ご家族が返す」→「職員に戻る」**

という短い往復に置き換えることを狙っています。

> なお、問い合わせの電話が施設長に集中する問題は、**直接なんとかしようとはしていません。** ご家族に情報が届くようになれば、問い合わせそのものが自然に減るはずだ、という考え方です。

## 3. 使う人は4種類です

| 立場 | どんな人 | この仕組みでの役割 |
|---|---|---|
| **施設の管理者** | 施設長など | 入居者・職員・ご家族の名簿をつくる。写真掲載の同意を記録する |
| **職員** | 現場の介護スタッフ | 写真を撮って送る。届いた反応を見る |
| **ご家族** | ご本人の配偶者・お子さん・お孫さんなど | 届いた様子を見る。ボタンで反応を返す |
| **入居者ご本人** | ご自分で操作できる方に限る | ご自分の端末から、ご家族へ直接送る |

### ご家族は「代表」を立てません

全員が同じように、同じ情報を、同じタイミングで受け取ります。「代表の方だけが見られる」「代表の方が他のご家族を追加する」といった仕組みは作りません。

### 入居者ご本人が使う場合について

入居者の方の中には、ご自分でスマートフォンを操作できる方もいらっしゃいます。そうした方は、**ご自分からご家族へ写真を送ることができます**。

- 「ご自分で操作できるかどうか」は、**施設の職員または管理者が判断して設定**します
- ご本人が自分でこの設定を変えることはできません
- 判断の理由や、診断名のようなものは**一切記録しません**。「できる／できない」だけを持ちます

## 4. 実際に何が起きるか（一日の流れ）

**午前10時、レクリエーションの時間。**

職員のさくらさんが、折り紙を折っている一郎さんの写真を1枚撮ります。画面で一郎さんを選び、送信。用意された文例から「楽しそうに過ごされています」を一回押して添えました。**ここまで1分かかりません。**

**その直後。**

- 松山で一人暮らしをしている奥さまのハナ子さん（82歳）のところに、お知らせが届きます
- 世田谷の長男・太郎さんにも届きます
- 福岡に住むお孫さんの美咲さんにも届きます

**3人が同時に、同じ写真を見ます。** 誰かの又聞きではありません。

**ハナ子さんは、写真の下のボタンをひとつ押します。**

文章は打ちません。その「ありがとう」は、施設の代表窓口ではなく、**写真を撮ったさくらさん本人**のところに届きます。

**夕方、さくらさんは自分の投稿に3件の反応がついているのを見ます。**

## 5. それぞれができること

### 職員ができること

- 入居者を選んで、**写真1枚＋短い文（任意）**を送る
- 文章は、あらかじめ用意された文例を**一度押すだけ**で入れられる（ゼロから書く必要はありません）
- 撮影から送信まで、**同じ端末の中だけ**で終わる（パソコンへの取り込みは不要）
- 送った投稿に届いた**反応を一覧で見る**
- **自分が送った投稿を削除する**

**誰に送るかを、職員は選びません。** 宛先は、その入居者に登録されているご家族の名簿から自動的に決まります。選ばせないことで、送り先を間違える余地と、毎回の判断の手間をなくしています。

**送る前の上司の承認もありません。** 承認を挟むと、そこで止まってしまうからです。間違えたときは、送ったあとに消せます。

### ご家族ができること

- 自分に紐づく入居者の様子を、**新しい順に**見る。過去にさかのぼることもできる
- 新しい投稿があると**お知らせが届く**
- **ボタンをひとつ押して**反応を返す
- お知らせを**止める**
- **ログアウトする**

**できないこと**：他の入居者の様子を見ることはできません。名簿を変えることもできません。

### 施設の管理者ができること

- 入居者を登録し、**退居**の扱いにする
- 職員を登録し、利用を止める
- **入居者ごとのご家族の名簿**をつくる・直す
- **写真を載せてよいかどうかの同意**を記録する
- 施設内のすべての投稿と反応を、**あとから確認する**
- 入居者が「ご自分で操作できる」かどうかを設定する（職員も設定できます）

**管理者は投稿できません。** 発信はあくまで現場で起きるべきもので、管理者が代行できるようにすると、結局その方の手作業に化けてしまうからです。

## 6. この仕組みが「やらないこと」

はじめから対象外と決めているものです。**できなかったのではなく、意図的に外しています。**

| やらないこと | 理由 |
|---|---|
| **緊急のご連絡** | 発熱・転倒などの急ぎの連絡には、確実に届く別の仕組みが必要です。**このシステムを緊急連絡の手段として使わないでください** |
| **介護記録（法律で定められた記録）の公開** | 記録はそのままご家族に見せるものではありません。この仕組みは、記録とは**別の道**として、日常の様子だけをお届けします |
| **医療・ケアプラン・ご請求の情報** | 扱いません |
| **外部への転送やSNSへの共有** | 写真が施設の外に広がる機能は用意しません |
| **健康状態や医療に関する情報** | そもそも**持ちません**。扱うのは日常の様子だけです。万が一情報が漏れたときの影響を、あらかじめ小さくしておくためです |

## 7. 安全とプライバシーについて

| | |
|---|---|
| **写真の同意** | 同意が記録されていない入居者の方については、**そもそも投稿できません**。これは職員が送るときも、ご本人が送るときも同じです |
| **他のご家族からは見えない** | ご家族が見られるのは、自分に紐づく入居者の情報だけです |
| **他の施設からは見えない** | 複数の施設が同じ仕組みを使いますが、施設をまたいでデータが見えることはありません |
| **写真の保護** | 写真は、たまたまアドレスを知った第三者が見られる状態にはしません |
| **退居されたとき** | ご家族からその入居者の情報が見えなくなります |
| **写り込みへの注意** | 写真に他の入居者の方が写り込む可能性があります。この点は運用上の注意として手順書に記載し、ご本人が投稿される場合にも施設からお伝えします |
| **責任の範囲** | 施設と、この仕組みを提供する側とで、個人情報の扱い・保存場所・事故時の連絡先を文書で取り決めます |

### 正直にお伝えしておくこと

**退居されたあとも、データそのものは残ります。** 最初の版では、データを消す機能を持っていません。削除のご要望があった場合は、提供する側が手作業で対応します。

これは、利用される施設・人数が限られているうちの割り切りです。必要になった時点で、消す機能を作ります。

## 8. 導入するときのこと

### 施設に用意していただくもの

- **すでにある**スマートフォンかタブレット（1台以上）。職員の私物でも構いません
- 入居者・職員・ご家族の名簿の情報

### 施設に用意していただかなくてよいもの

- 新しい端末の購入 — **不要です**
- 施設内へのサーバーなどの機器の設置 — **しません**
- クラウドの契約や、専門的な環境の準備 — **一切ありません**

> 施設側で行っていただくのは**最初の名簿登録だけ**です。専門的な作業が入口にあると、そこで導入が止まってしまうためです。

### ご家族に必要なもの

- スマートフォン（**発売から5年程度前の機種でも動きます**）
- **アプリを入れる必要はありません**。普段お使いのインターネットの画面で見られます

### 費用と運用

- 1施設あたり**月額1万円程度を上限**に収まることを目標にしています
- 導入・運用・困ったときの手順は、すべて**日本語**でご用意します

### 想定している規模

1施設あたり、入居者80名・職員50名・ご家族200名くらいまで。入居者お一人あたり月10回ほどの投稿を見込んでいます。

## 9. 高齢のご家族にとって、どこまで使いやすいか

この仕組みは「**スマートフォンはメッセージのやりとりにしか使わない**」という高齢のご家族を基準に作っています。

**満たすようにしていること：**

- 説明を読まなくても、目的にたどり着けること
- 文字は大きく（端末側で文字を大きくしていても崩れません）
- ボタンは大きく、間隔をあけて
- 「同期」「セッション」といった**専門用語やカタカナ語を画面に出さない**こと
- 横になぞる・長押しする・何階層もたどる、といった操作を**必要としない**こと（縦に動かして、押すだけ）
- 写真を画面の主役として、大きく表示すること

### ただし、最初の版では届かないところがあります

**最初に一度だけ、ログインの操作が必要です。**

これは正直に申し上げます。この仕組みがもともと目指していたのは、**覚えることも入力することもいらない入口**でした。それがあってはじめて、82歳のハナ子さんのような方が**ご自分一人で**使い始められるからです。

しかし、それを実現する方法が、**安全面でも作る手間の面でも、最初の版には重すぎる**と判断しました。そのため最初の版は、一般的なログインの方式で出します。

**その結果どうなるか：**

- 画面を見る操作・反応を返す操作は、高齢のご家族の水準に合わせてあります
- しかし**使い始めの最初の一回だけは、ご家族の誰かの手助けが必要になる可能性があります**
- 「ログイン」「パスワード」という言葉は、**その最初の画面にだけ**登場します。使い始めたあとの画面には出しません
- 一度入っていただければ、**同じ端末では入力し直す必要はありません**。しばらく使わなかったとき、またはご自分でログアウトされたときだけ、もう一度お願いします

この課題は、なくなったのではなく**次の段階に持ち越し**ています。

## 10. うまくいったと言えるかどうか

導入から3ヶ月後、次のことを見ます。**数字はいまのところ仮置き**で、実際に使われはじめてから見直します。

| 見ること | 目標 |
|---|---|
| どれくらいの頻度で送られているか | 入居者の8割について、**週2回以上**が続いている |
| 1回の投稿にかかる時間 | **60秒以内**（実際の端末で計測します。作った側の感覚では判定しません） |
| ご家族から反応が返っているか | **半分以上**の投稿に反応がついている |
| ご自分で操作できる入居者が、実際に使ったか | （目標値は未定。使われなければ、この機能自体を見直します） |

> 「問い合わせの電話が減ったか」も見たい項目ですが、施設のご協力なしには測れないため、最初の版では追いません。
> 「高齢のご家族がお一人で使えたか」も、9章のとおり最初の版では達成できないため、測りません。

## 11. 最初の版では見送ったこと

「やらないこと」（6章）が**方針として対象外**であるのに対して、こちらは**必要だと認めたうえで、最初の版からは外した**ものです。あとで戻せるように、理由を残しています。

| 見送ったもの | どなたの要望か | なぜ見送ったか |
|---|---|---|
| 覚えることも入力することもいらない入口 | 高齢のご家族 | 安全面と作る手間の両方で、最初の版には重すぎる。まず「送られ続けるか・反応が返るか」を先に確かめる |
| お知らせを「1日1回まとめて」にする設定 | 通知が多いのを避けたいご家族 | 投稿が週2〜3回である限り、通知が連続することは起きない。**設定項目を作らないこと自体**が、高齢のご家族への配慮でもある |
| ご家族から職員への短いコメント | ご家族 | ボタンひとつの反応で目的は果たせる。コメントは職員の返信の負担に上限がなくなるため、まず反応の実績を見てから |
| ご家族が自分で親族を追加する | ご家族の代表の方 | 申請と承認の手続きが増える。頻度の低い操作なので、管理者へのご依頼で代替できる |
| 施設からご家族のアクセスを個別に止める操作 | 施設の管理者 | 退居時には自動で止まり、使われていない状態も一定期間で自動的に切れる。この2つで足りない場面が実際に出てきてから作る |
| 通信が弱いときの写真の自動再送 | 現場職員 | **作る手間が最も大きい項目でした**。送信に失敗したら、職員はその場にいるので撮り直して送り直せます |
| 誰がいつ何を消したかの記録 | 施設の管理者 | 管理者は施設内の投稿と反応をあとから見られるため、それで足りるとしました |
| 入居者ごとの最終投稿日・投稿件数の一覧 | 施設の管理者 | 「送られ続けているか」は確かめたい項目ですが、画面の機能として作る必要はありません |
| 退居時にデータを残すか消すかの選択 | 施設の管理者 | 7章のとおり、最初の版はデータを保持します |
| 書きかけの投稿が消えないようにする | 現場職員 | 呼び出しで中断されることはありますが、必須の入力は写真1枚だけなので、失われるものが小さい |
| 入居者の「人となり」の共有 | ご家族・職員 | 価値は認めますが、いま挙げた課題のどれも解決しません。往復が回り始めてから |
| 施設ごとの文例の書き換え | 施設の管理者 | 用意した文例で始めます。ご要望が出てから |

### 見送ったことで受け入れているリスク

はっきり書いておきます。

1. **通信が弱い場所では、投稿が失敗したまま失われることがあります**
2. **誰が投稿を消したのかを、あとから追うことができません**
3. **退居されたあともデータが残り続けます**

いずれも「実際に困ることが起きてから作る」という判断です。利用の規模が限られているうちの割り切りであることを前提にしています。

## 12. 言葉の説明

| このページでの言い方 | 意味 |
|---|---|
| **最初の版** | いちばん最初に作って、実際に使っていただく版のこと。確かめたいことを絞るため、機能をわざと少なくしています |
| **投稿** | 職員（またはご本人）が送る、写真1枚と短い文のひとまとまり |
| **反応** | ご家族がボタンひとつで返す気持ち。文章は入りません |
| **名簿** | どの入居者に、どのご家族が紐づいているかの一覧。施設の管理者だけが編集できます |
| **同意** | 写真を載せてよいという、ご本人またはご家族の意思の記録 |
| **次の段階** | 最初の版を実際に使ってみたあとに作る、次の版のこと |
