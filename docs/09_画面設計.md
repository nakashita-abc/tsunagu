## 職員ホーム画面（`/staff`）

### 目的

職員が手元の端末を開いて最初に見る画面。求められる操作は次の2つ。

- 投稿作成画面への遷移
- 自分の投稿に対する家族の反応に気づくこと

### 表示要素

1. **投稿をつくる**（ボタン。画面最上部・最大の要素）
   - 遷移先：投稿作成画面
2. **自分への最新の反応**（直近2件・時刻降順）
   - 未読／既読の概念は持たない（要件定義に該当要件が無いため、単純に時刻順で出す）
   - 件数を増やす場合も、表示件数の変更のみで対応できる想定
3. **自分の反応をすべて見る導線**（一覧画面へのリンク）
   - ホームには直近2件のみを置き、詰め込まない
   - 遷移先の一覧画面は未検討（次のTODO）

### スコープ外（今回は含めない）

- **他職員の投稿に対する反応の表示。** 要件定義書 3-2 権限マトリクスで、職員が閲覧できる反応の範囲は「自分の投稿への反応」に限定されている（施設全体の反応閲覧は施設管理者のみ）。この制約と一致させ、ホーム画面は自分宛ての反応のみを扱う。

### 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 最新の反応の件数 | 直近2件 | 投稿作成の導線を画面内で最大の要素として保つため、反応表示は最小限に絞る |
| すべての反応を見る手段 | 別画面への導線を1本だけ置く | ホームに情報を詰め込まない方針と、直近だけでは足りない場合の受け皿を両立させる |
| 未読の概念 | 持たない。表示順は時刻降順のみ | 要件定義に未読管理の要件が無いため |
| 他職員の反応の扱い | 表示しない（スコープ外） | 権限マトリクス（05_要件定義.md 3-2）が職員の反応閲覧を「自分の投稿への反応」に限定しているため |

## 自分の反応をすべて見る画面（`/staff/reactions` 仮）

### 目的

職員ホーム画面の「自分への最新の反応（直近2件）」を全件見るための画面。表示する情報の種類はホームと同じで、**件数の制限だけを外したもの**。

### 表示要素

1. **自分への反応の一覧**（時刻降順。ホームと同じ表示項目）
2. **もっと前を見る**（ページ送り。明示的なボタンで区切る）
3. **ホームに戻る導線**（この画面を行き止まりにしない）

### 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 「全件」の出し方 | 一度に全件は返さない。「もっと前を見る」ボタンでページ送りする | 職員が働き続ける限り反応は増え続けるため、無制限に一覧を返す設計は破綻する。無限スクロールも採らない |
| ホームへの戻り方 | 明示的な戻り導線を置く | 行き止まりの画面を作らないため |
| 「投稿をつくる」ボタン | **置かない** | この画面は反応閲覧に徹する。投稿作成への導線はホーム画面だけに絞り、画面の役割を単純に保つ |
