# 設計ルール

## 1. 要件との整合性
- 要件定義書を確認してから設計する
- 要件にない機能を追加しない
- 不明点を推測で確定せず、確認事項として提示する

## 2. 既存設計との整合性
- CLAUDE.mdと既存の設計書を確認する
- 既存のアーキテクチャ、命名規則、依存方向に従う
- 既存設計から逸脱する場合は理由を説明する

## 3. YAGNI・KISS
- 現時点で不要な機能や抽象化を設計しない
- 要件を満たす最も単純な構成を優先する
- デザインパターンを目的なく導入しない

## 4. 責務と依存関係
- 各コンポーネントの責務を明確にする
- 責務の重複や不必要な結合を避ける
- レイヤー間の依存方向を守る

## 5. 設計判断
- 重要な技術選定には採用理由を記載する
- 必要に応じて代替案とトレードオフを示す
- 要件から判断できない事項は決めつけない

## 6. 検証可能性
- 正常系、異常系、境界条件を考慮する
- 入出力、制約、エラー時の振る舞いを明確にする
- テスト可能な単位で責務を分離する
